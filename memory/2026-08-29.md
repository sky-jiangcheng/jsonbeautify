# 2026-08-29

## 状态栏消失事故闭环 + 架构加固 (v1.5.60 → v1.5.62)

**事故**: Mac App Store / PC 版状态栏消失、长文本底部滚不出 (v1.5.55~v1.5.59)。
根因: router.js detect() 用 innerWidth≤900 判 mobile，Tauri 壳初始化瞬间
innerWidth 短暂 ≤900 → 整个 UI 误入 mobile 层。PWA 正常、封壳必炸。

**修复链**: v1.5.60 Tauri 强制 desktop → v1.5.61 加 hover+pointer 条件防 iPad
误伤 → v1.5.62 架构性根治。

**v1.5.62 架构改造（四步全做）**:
1. 设备类别单源化: detect() 只用稳定信号 (UA / hover+pointer)，
   innerWidth 彻底移出设备判定；宽度自适应归 CSS @media。
   副作用(有意): 桌面浏览器窄窗口不再切移动 UI，保持桌面层+堆叠，
   顶栏加了横向滚动保护。真手机/平板行为不变(UA/触摸判定)。
2. CSS 拆分: [data-device="mobile"] 规则(129行)全部移入 styles.mobile.css，
   build.js 复制、sw.js 预缓存、index.html 在 styles.css 后加载。
   拆分脚本 /tmp/wktest/split_css2.py (括号感知扫描器,注释前置会破坏
   startswith("@media") 判定——已修)。4视口×23选择器×11属性与基线零差异。
3. 版本单源化: version.json 是唯一源；npm run bump -- X.Y.Z 写源并同步
   7 文件；build.js 构建前自动 sync(靠这个保证 CI 门禁永远一致)。
   注意: replace 回调签名要写全 3 个组 (m,g1,g2,g3)，丢了 g2 会把旧版本
   拼接回填，写坏文件(git checkout 可救)。
4. 冒烟测试: tests/layout.spec.mjs (playwright-core + 系统 Chrome channel,
   免下载内核) 6 场景 22 断言: 桌面/窄窗/极窄390/Tauri壳/手机长文本/iPad。
   workflow: layout-tests.yml (push main + PR)。

**教训**:
- 本地测试端口被 SW 旧缓存接管会让验证结果失真——每次验证换新端口。
- "修A端坏B端"的根源是多套判定系统并存，不是某行代码。
- ZCode 内嵌浏览器 matchMedia 上报正常，但 UA/触摸桩要 runtime 注入。

## v1.5.64: UI 层规则再修正 (用户反馈驱动)

用户反馈: 窄窗下移动设计全没了(More 按钮/抽屉历史), History 占屏 1/3 不可接受。
确认: 移动端原设计是 History=全屏抽屉(more 唤起), v1.5.62 发明的"窄窗桌面堆叠"
方案体验错误。

最终 UI 层规则 (router.js):
  mobile 层 = 真触屏设备(UA/指针稳定判定) 或 桌面浏览器视口≤900px
  desktop 层 = 其余; Tauri 桌面壳锁定 desktop(壳内宽度不可信,v1.5.55~59 教训)
即: 设备类别稳定 + 仅桌面浏览器引入宽度维度。Tauri 壳窄窗保留桌面堆叠布局。
